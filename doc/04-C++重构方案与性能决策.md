# 04 C++ 宽带 Ray-Reuse 重构方案与性能决策

## 1. 重构目标

新程序不是 Bellhop 的 C++ 全量移植，而是一个面向固定场景的二维宽带声场求解器：

```text
固定环境 + 固定源/接收网格 + 多个频率
              ↓
每个发射角只追踪一次几何声线
              ↓
逐频重建吸收、反射和波束状态
              ↓
输出 broadband coherent pressure field
```

“固定”指一次宽带运行内这些条件不变化；不同运行仍可以加载不同环境和收发配置。

## 2. 是否采用 C++：结论

### 2.1 核心判断

C++ 不会仅凭语言选择就明显快于 Fortran。对相同算法、相同数据精度和相近编译优化，现代 C++ 与 Fortran 通常会生成相近的标量/向量指令；规则数组循环中 Fortran 甚至可能更容易获得良好自动向量化。

本项目的主要性能收益按重要性排序是：

1. ray reuse：消除每个频率重复的几何追踪；
2. 并行任务划分：让不同线程无竞争地计算不同频率的场；
3. 移除原代码模块级全局可变状态，使声线可重入；
4. 合理的数据布局、批处理、向量化和缓存使用；
5. 最后才是语言和标准库层面的常数优化。

因此，不能把“换成 C++”直接等同于“运行更快”。

### 2.2 建议

建议采用 C++，但采用理由和条件应写成：

> 项目本来就需要裁剪 Bellhop 模式、重构数据流并建立新的并行架构；团队愿意承担一次完整数值回归；C++ 原型通过明确的性能门槛。

如果唯一目标是最短时间获得并行加速，现代 Fortran + OpenMP 同样能实现 ray reuse 和频率并行，而且保留现有数值代码的验证成本更低。当前 Fortran 难并行的真正原因是 `ray2D`、`iSeg*`、Influence 临时变量和 `U` 都含有共享全局状态，而不是 Fortran 语言本身。

由于本项目已经主动删除大多数 Bellhop 模式，并希望长期进行线程控制、数据布局和可能的 GPU/异构扩展，C++ 重构具有工程价值。结论是“有条件推荐 C++”，不是无条件重写。

### 2.3 性能决策门槛

在完整移植 Influence 之前建立代表性原型。建议初始门槛：

- C++ 单线程核心算子相对优化后的 Fortran 不慢于 20%；
- 8 个物理核心上，代表性宽带案例端到端加速达到至少 4 倍；
- 64 频案例中几何追踪调用次数不随频率数增长；
- 并行结果与单线程结果满足复压力误差标准；
- 峰值内存处于目标机器可接受范围。

若 C++ 原型未通过门槛，应先检查任务划分和数据布局；仍无法通过时，保留 Fortran 并实施同样的算法重构更合理。

这些门槛是项目初始 go/no-go 标准，可在拿到目标硬件和真实案例后调整。

## 3. 功能范围决策

### 3.1 首版必须保留

- 二维 `(r,z)`；
- 多频输入；
- 固定源位置和 rectilinear 接收网格；
- coherent complex pressure/TL；
- Cartesian Cerveny Gaussian beams，对应原版 `CC` 主路径；
- 中心射线和动态射线 `p/q`；
- 真空海面；
- 刚性及声学半空间海底；
- C-linear SSP，随后扩展其他插值；
- 水体及海底频率相关衰减；
- SHD 输出和诊断日志。

### 3.2 明确删除

- ray plot、eigenray、arrivals；
- incoherent 和 semi-coherent TL；
- 3D/Nx2D；
- irregular receiver grid；
- 速度分量输出；
- beam shift；
- 多套 beam type 的运行时切换；
- Fortran 文件单元号和模块级全局状态兼容。

### 3.3 延后但不阻塞架构

- 距离相关 bathymetry/SSP；
- tabulated reflection coefficient；
- 多源深度；
- 频率分块和并行化；
- 其他 SSP 插值方式。

## 4. 推荐工程结构

建议使用 C++20 和 CMake：

```text
cpp/
  CMakeLists.txt
  include/rayreuse/
    model/          Environment, SSP, Boundary, Grid
    numerics/       Vec2, interpolation, root/intersection
    ray/            GeometryTracer, RayPath, ReflectionEvent
    broadband/      FrequencyProjector, Attenuation
    field/          CervenyInfluence, BroadbandField
    io/             EnvReader, ShdWriter
  src/
  app/
    rayreuse_main.cpp
  tests/
    unit/
    regression/
    golden/
```

首版不要设计庞大的运行模式继承树。对于唯一的计算模式，组合明确的数据和服务对象比抽象 `RunMode`/`BeamMode` 基类更简单。

## 5. 核心对象

### 5.1 不可变输入模型

```cpp
struct SimulationCase {
    Environment environment;
    Source source;
    ReceiverGrid receivers;
    std::vector<double> frequencies;
    LaunchFan launchFan;
    IntegratorSettings integrator;
};
```

构造完成后不再修改环境。所有 evaluator 使用 `const` 接口，防止逐频更新破坏共享几何状态。

### 5.2 几何轨迹

`RayPath` 保存：

- `position/slowness/p/q/c/realTravelTime`；
- 每步积分的中点或等价求积信息；
- 反射事件和边界段；
- 终止原因。

仅保存最终轨迹点可能不足以严格重建原 Step 的复时间积分。建议保存每步的 `h、hw0、hw1` 及中点位置，或设计等价的 `StepQuadrature`。

### 5.3 逐频投影

`FrequencyProjector` 只读取 `RayPath` 和不可变环境，生成临时 `RayFrequencyState`：

- complex travel time；
- cumulative amplitude/phase；
- reflection coefficient；
- active mask。

该临时状态在一次 Influence 累加后即可释放。

## 6. 数据流与内存策略

优先采用“逐射线流式复用”：

1. 追踪一个发射角的 `RayPath`；
2. 遍历所有频率并累加到 `BroadbandField`；
3. 释放该路径；
4. 处理下一发射角。

这样真正复用了几何计算，又避免保存全部声线。主要内存为：

```text
O(Nfreq × Nreceiver) pressure field
+ O(Nsteps) current ray
```

若压力场过大，再引入频率分块；代价是每个频率块需要重新追踪一次射线扇。

### 6.1 推荐 CPU 并行结构

直接并行发射角会让多个线程同时写同一个压力场，必须使用原子操作、锁或线程私有全场归约，成本较高。推荐采用角度批次：

```cpp
for (AngleBatch batch : launchAngleBatches) {
    parallel_for(batch.angles, [&](double angle) {
        paths[angle] = tracer.trace(source, angle);
    });

    parallel_for(frequencyIndices, [&](std::size_t fi) {
        auto fieldSlice = field[fi]; // 当前任务独占该频率切片
        for (const RayPath& path : paths) {
            auto state = projector.project(path, frequencies[fi]);
            influence.accumulate(fieldSlice, path, state, frequencies[fi]);
        }
    });
}
```

优点：

- 几何追踪在角度维度并行；
- 声场贡献在频率维度并行；
- 每个频率切片只有一个任务写入，无复数原子加法；
- 同一频率内保持固定角度累加顺序，结果更容易复现；
- 一个批次结束后释放声线路径，内存可控。

当 `Nfreq >= 线程数` 时，该结构能提供充足并行度。若频率数很少，再增加 receiver tile 或线程私有小块归约，不应首先并行最内层每个接收点。

### 6.2 数据布局

- 压力场采用 frequency-major：`field[fi][iz][ir]`；
- `ir` 连续，匹配 Influence 对接收距离的遍历；
- 声线路径热点字段可采用 SoA，便于加载和向量化；
- 内部使用 `double/std::complex<double>`，输出时转换；
- 避免在接收点内层循环分配对象或进行虚函数调用。

### 6.3 预期收益边界

ray reuse 只减少 Trace 部分。若真实案例主要耗时在 Influence，则串行复用加速有限，必须依赖上述频率并行。64 个频率具备较好并行度，但实际扩展会受核心数、内存带宽、不同频率工作量和波束窗口影响，不能预先承诺接近 64 倍。

现有测试 PRT 显示大案例运行时间约 11900 秒，但其可执行文件与源码不一致，且缺少分阶段计时，不能据此推算 C++ 加速比。必须先剖析 Trace、Project、Influence 和输出占比。

## 7. 从 Fortran 迁移，而不是逐行翻译

推荐迁移顺序：

1. 数据与单位：环境、SSP、边界、角度、网格；
2. SSP evaluator：`c/grad/Hessian`；
3. 单步积分器；
4. 边界落点和几何反射；
5. 动态 `p/q` 跳跃条件；
6. 单频 Cartesian Cerveny Influence；
7. SHD 输出；
8. 多频投影；
9. ray reuse 循环重排。

不要一开始就同时改变积分算法、波束公式、文件格式和宽带循环。每迁移一层，都应能与 Fortran 或解析结果独立比较。

## 8. 难度评估

### 8.1 总体结论

在裁剪到二维 `CC` coherent TL 后，工程规模显著小于完整 Bellhop，但仍属于高难度数值重构，而不是普通语言迁移。

- 裁剪后的可用 MVP：约 `7/10`；
- 达到稳定、可验证的研究计算工具：约 `8/10`；
- 若要求覆盖原 Bellhop 全部边界和插值细节：约 `9/10`。

最大的困难不是 C++ 语法，而是保持焦散、边界反射、动态射线和复相位的数值行为。

### 8.2 分项难度

| 工作项 | 难度 | 主要原因 |
|---|---:|---|
| 理论规范化 | 中 | HTML 关键笔误已修订，但符号 `p` 仍多义 |
| SSP 与导数 | 中高 | Influence 和动态射线依赖二阶导数 |
| 中心射线积分 | 中高 | 动态步长、界面落点、状态索引 |
| 动态 `p/q` | 高 | 焦散、基本解、边界跳跃条件 |
| 边界处理 | 高 | 掠射、重复点、曲率和反射事件 |
| Cerveny Influence | 很高 | 复平方根分支、KMAH、波束窗口 |
| 多频投影 | 中高 | 吸收、反射幅相和 active mask |
| SHD 兼容 | 中 | direct-access 记录布局和精度 |
| 数值验证 | 很高 | 复压力对相位误差极敏感 |
| 性能优化 | 中高 | 射线并行会放大场累加内存 |

### 8.3 粗略工作量

对熟悉 C++、数值 ODE 和水声射线法的一名开发者：

- 最小解析环境原型：约 3–5 周；
- 可与单频 Fortran 对比的 `CC` MVP：约 8–12 周；
- 加入可靠边界损失、宽带复用、SHD 和回归：约 12–20 周；
- 工程化、性能和更多环境选项：在此基础上继续迭代。

这些是风险评估量级，不是承诺工期。若缺少可信的 Fortran 构建基线，验证阶段可能成为最长路径。

## 9. 主要技术风险

### 9.1 缺少可信行为基线

仓库现有 `test/bellhop.exe` 与源码不一致。必须先建立可重现的 Fortran 单频基线；否则 C++ 与二进制不一致时无法判断谁正确。

### 9.2 Influence 比追踪更难移植

几何路径复用的理论较清晰，但声场结果最终由 Influence 决定。复根分支、KMAH 指数和焦散附近处理只要略有差异，就会造成明显相位/幅值误差。

### 9.3 轨迹点不足以重建频率损失

原积分器使用中间点和动态步长权重。若 C++ 只缓存端点，逐频重算复 `tau` 可能与单频基线产生系统误差。

### 9.4 并行化过早

按射线并行需要线程私有压力场或细粒度同步。`Nfreq × Nreceiver` 很大时，线程私有场会迅速增加内存。首版应保持串行、正确、可测量。

## 10. 验证金字塔

```text
解析解
  等声速直线、动态 q、简单反射
        ↓
组件对比
  SSP/Step/Reflect/Influence 与 Fortran 中间状态
        ↓
单频端到端
  C++ single frequency vs reproducible Fortran
        ↓
宽带非复用基线
  一次运行逐频完整追踪
        ↓
宽带 ray reuse
  reuse vs 独立单频复压力
```

已有未知来源二进制只作为补充观察，不作为唯一 oracle。

## 11. 架构决策

- 使用 `double` 保存轨迹、动态状态和复相位；SHD 写出时按格式转单精度。
- 环境对象不可变；频率作为显式参数，不使用全局 `freq/omega`。
- 第一版复现 Bellhop modified Heun/box 积分，不更换求解器。
- `RayPath` 显式记录反射事件和求积数据。
- 逐射线流式处理全部频率。
- 只实现一种明确的 Influence，不保留无用模式抽象。
- 正确性通过后再做 SIMD、OpenMP 或任务并行。

## 12. 推荐首个里程碑

首个里程碑应是：

> C++ 在等声速、真空海面、刚性平底环境中，对一个源、规则接收网格和 2–3 个频率，只追踪一次射线扇，并得到与独立单频计算一致的 coherent complex pressure。

它暂不包含真实海底损失和复杂 SSP，但可以同时验证中心射线、动态射线、Cartesian Cerveny Influence、宽带循环和 ray reuse 数据流。
