## 当前结论

项目目标已收敛为：参考原 Bellhop 数值行为，构建二维宽带相干声场计算；环境、收发位置和发射角集合在一次运行中固定，只追踪一次几何声线，再对多个频率重算损失、反射、波束宽度和复压力。

C++ 是当前有条件推荐的实现语言，理由是便于构造不可变环境、线程局部声线状态、频率所有权明确的压力场和后续性能工程，而不是 C++ 标量计算天然快于 Fortran。最终采用决定受 `01` 主文档中的性能门槛约束。

本次修改整体排除 beam shift。在实声速和环境几何不随频率变化的目标范围内，几何声线状态 `x/t/p/q` 可以跨频率复用；传播吸收、边界反射系数、波束参数及最终声场贡献仍需逐频计算。

针对当前“轨迹数量可控、宽带目标点较少”的使用特征，正式数据流采用“先缓存完整只读 `RayPathCache`，再逐频或有界并行遍历全部轨迹”。压力场只为活动频率分配，某频率写出后立即复用缓冲区，因此压力工作区不随总频率数无界增长。

`.env/.shd` 保留为首版 Bellhop 兼容输入输出，但文件解析与写入必须与数值核心解耦。计算内部使用不可变 `SimulationCase`、单频 `FrequencyWorkspace` 和有界输出队列；HDF5 作为大规模结果的后续候选，不阻塞当前 SHD 数值回归。

当前代码基线应视为原始、单频 Bellhop 模型。仓库中的 `freqVec`、部分多频 SHD 头处理和宽带测试结果，是此前多频尝试时拷入的实验文件，不代表原始模型已经具备宽带基础设施。

原版 2-D Bellhop 的可重现构建基线已建立：项目根目录执行 `mingw32-make -C Bellhop_origin` 会生成默认的 release/static `Bellhop_origin/bin/bellhop.exe`。已通过 PE 导入表确认该文件不依赖 `libgfortran`、`libquadmath`、`libgcc` 或 `libwinpthread` DLL；它仍正常依赖 Windows 系统 DLL，运行时也必须带上 `.env` 及其引用的环境输入文件。

## 当前实施范围

第一阶段不重写原 Bellhop 的所有运行模式，只保留：

1. 二维、固定环境、固定收发位置；
2. 多频 coherent TL；
3. Cartesian Cerveny 波束（对应原版 `CC` 路径）；
4. rectilinear 接收网格和压力分量；
5. SHD 输出及逐频单跑回归。

`R/E/I/S/A/a`、3D、arrivals、eigenray 等模式不进入首版 C++ 范围；beam shift 在本次修改中完全不考虑。

最终发射角数目由输入频率最大值按原 Bellhop 的经验估算和充分性检查共同确定，所有频率共享同一发射角集合。每个反射事件必须显式记录碰撞对象为海面或海底。
