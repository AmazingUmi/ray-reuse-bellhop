# 00 Bellhop 宽带 Ray-Reuse 文档索引

本目录记录 Bellhop 二维 Fortran 源码分析、射线理论、宽带轨迹复用设计、C++ 重构决策、实施待办和构建方法。

当前项目目录按职责分离：

- `Bellhop_origin/`：可重现的二维 Fortran oracle 及其 Makefile；
- `Bellhop_F2CPP/`：独立的优化版 C++ 单频复刻，负责建立 M1/M2 组件级、端到端和性能参照；
- `Bellhop_RayReuse/`：由已验收 F2CPP 代码派生，随后独立实现 M3～M5 宽带非复用、轨迹缓存和有界频率并行；
- `test/PlotRead/`：集中保存 Python `bellhop_io_py` SHD 读取/绘图工具、读取回归和 Acoustic Toolbox MATLAB 格式参考；
- `test/standard_cases/`：原版、F2CPP 和 RayReuse 共用的单频/宽带算例定义、执行矩阵与比较规则；
- `test/legacy/`：迁移前的原版和宽带实验材料，不参与活动测试。

`Bellhop_F2CPP` 是 RayReuse 的先行实现和源码重构基线：先完成并验收 F2CPP，再复制/派生必要代码到 RayReuse。派生后两者拥有独立源码副本、构建系统和可执行程序，不形成持续的链接、头文件或运行时依赖；F2CPP 还继续提供标准算例和数值参照。

## 当前结论

项目目标已收敛为：参考原 Bellhop 数值行为，构建二维宽带相干声场计算；环境、收发位置和发射角集合在一次运行中固定，只追踪一次几何声线，再对多个频率重算损失、反射、波束宽度和复压力。

C++ 是当前实现语言，理由是便于构造不可变环境、线程局部声线状态、频率
所有权明确的压力场和后续性能工程，而不是 C++ 标量计算天然快于 Fortran。
F2CPP 和 RayReuse 的数值、独立性及性能门已经通过，当前证据统一从
[`Bellhop_RayReuse/doc/README.md`](../Bellhop_RayReuse/doc/README.md) 进入。

实施顺序已经冻结为：**先在 `Bellhop_F2CPP/` 完成优化版 C++ 单频复刻并通过验收，再以该代码为起点派生 `Bellhop_RayReuse/`，验证其单频/宽带非复用基线，随后实现串行 Ray-Reuse，最后加入有界频率并行**。测试、文档和接口设计可以并行准备；RayReuse 核心代码实施遵循上述先后顺序。派生关系不转化为持续的编译或运行依赖。

F2CPP 的“单频”只表示一次运行仅计算一个频率，不表示采用临时单频数据结构。M1/M2 阶段必须落实完整 `RayPathCache`：缓存中心射线状态、动态 `p/q`、实走时、步进求积信息、反射事件和终止原因；逐频复走时、反射幅相、有效状态及压力进入独立工作区。这是 F2CPP 验收和后续派生 RayReuse 的首要架构门禁。

本次修改整体排除 beam shift。在实声速和环境几何不随频率变化的目标范围内，几何声线状态 `x/t/p/q` 可以跨频率复用；传播吸收、边界反射系数、波束参数及最终声场贡献仍需逐频计算。

针对当前“轨迹数量可控、宽带目标点较少”的使用特征，正式数据流采用“先缓存完整只读 `RayPathCache`，再逐频或有界并行遍历全部轨迹”。压力场只为活动频率分配，某频率写出后立即复用缓冲区，因此压力工作区不随总频率数无界增长。

`.env/.shd` 保留为首版 Bellhop 兼容输入输出，但文件解析与写入必须与数值核心解耦。计算内部使用不可变 `SimulationCase`、单频 `FrequencyWorkspace` 和有界输出队列；HDF5 作为大规模结果的后续候选，不阻塞当前 SHD 数值回归。

原始 Fortran 目录继续作为单频 oracle；`Bellhop_RayReuse` 已完成 A～G、
F1/F2 和 H1～H3，包括独立 C++20 实现、宽带 nonreuse、串行 reuse、有界
频率并行、性能收敛、三模型矩阵和中间状态门。下一项本地工作是 H4 的
AppleClang/GCC 交叉编译器验证。

原版 2-D Bellhop 的可重现构建基线已建立：项目根目录执行 `mingw32-make -C Bellhop_origin` 会生成默认的 release/static `Bellhop_origin/bin/bellhop.exe`。已通过 PE 导入表确认该文件不依赖 `libgfortran`、`libquadmath`、`libgcc` 或 `libwinpthread` DLL；它仍正常依赖 Windows 系统 DLL，运行时也必须带上 `.env` 及其引用的环境输入文件。

## 当前实施范围

第一阶段不重写原 Bellhop 的所有运行模式，只保留：

1. 二维、固定环境、固定收发位置；
2. 多频 coherent TL；
3. Cartesian Cerveny 波束（对应原版 `CC` 路径）；
4. rectilinear 接收网格和压力分量；
5. SHD 输出及逐频单跑回归。

`R/E/I/S/A/a`、3D、arrivals、eigenray 等模式不进入首版 C++ 范围；beam shift 在本次修改中完全不考虑。

最终发射角数目由输入频率最大值按原 Bellhop 的经验估算和充分性检查共同确定，所有频率共享同一发射角集合。每个反射事件必须显式记录碰撞对象为海面或海底。
